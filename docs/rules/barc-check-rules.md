## 1. 下單資料來源（2026-10-01 起）

每家上手的下單／詢價 Excel 格式不同，**以上手原始格式為準**，不再使用整理過的 `FCN參考條件.xlsx`。每家上手一份格式設定（`config/order_formats/<上手>.toml`），把原始欄位轉成標準欄位後再與說明書比對。新增上手時，詢價表欄名對應可只靠設定與格式文件；說明書 parser 與上手專屬規則須另外實作，流程見[新增上手實作規範](../issuer-onboarding.md)。

- 目前支援：BARC 詢價表，一筆交易一個檔（暫定）。
- 未在設定中列出的欄位、未知的欄位值 → 轉人工覆核。

## 2. 不核對的項目（使用者確認）

- 詢價表中 TS 沒有對應資料的欄位：Product、Upfront / Note Price、OTC、Funding Spread、Notional、Quote ID。
- ISIN：詢價表沒有，暫不核對（PASS）。
- 標的名稱（中英文）：上手以彭博代號索引自動帶入名稱，只核對代號（§3.6、§6.2；2026-10-02）。
- 最初價格本身的外部正確性：沒有權威來源（詢價表沒有各標的進場價），只核對以它推算的執行／KO／下限價與重印表（2026-10-02 排除）。
- 情境分析有利情況的平均年化報酬率、最差情況的報酬率：取決於假設的持有期間與最終價格，沒有固定基準（例：有兩份樣本的有利情況年化率遠高於年利率）。

**保證配息期（Guaranteed Periods）**：保證配息、不會被 KO 的期數（2026-10-01 確認）。

| KO 型態 | PDF 表格 | 保證配息期 |
|---|---|---|
| Daily | §13(7) 期間表第 1 期期始日有日期（發行後即開始每日觀察） | 0 |
| Daily | 第 1～G−1 期整列 `N/A`，第 G 期期始日 `N/A`、期末日有日期 | G |
| Period End | 評價日表：前 G 期註記 `(非自動提前出場評價日)`，第 G+1 期起可 KO | G（例：前 11 期註記 → 11） |
| Period End | 自動提前出場評價日表或沒有任何註記（第 1 期評價日即可 KO） | 0 |

換句話說：Period End 型 = 第一個可 KO 期 − 1；Daily 型若第 1 期只在期末日觀察，則 = 第一個可 KO 期。

比價日：詢價表沒有各期觀察日，改以 PDF 內部日期規則（§3.8）檢查。

### 3.4 數值與小數位

- Excel 數字可能有二進位浮點尾數（例：`x.xx64999999994`），先四捨五入到 9 位小數清掉尾數。
- 百分比：比到 PDF 顯示的位數（2 位）。
- 價格：詢價表沒有價格。PDF 內部檢查各標的執行價、KO 價、下限價 = 進場價 × 對應百分比，四捨五入（half-up）到 4 位（14 份樣本 82 項全部成立）。進場價本身目前沒有外部來源可比。日後若有外部價格來源，價格一律四捨五入到 4 位後比對。

### 3.5 月配息率（2026-10-01 確認）

- **總配息率是正確值**：總配息率 = 下單資料年利率 × 天期 ÷ 12。
- 推算月配息率 = 總配息率 ÷ 商品期數（期數 = PDF 配息表列數，目前每月一期，等於天期）。
- 推算值與 PDF 月配息率**差距 ≤ 0.0001 視為一致**；超過才判不一致。

背景：用上式四捨五入到 4 位，14 份樣本中有 4 份（S06、S08、S10、S12）比 PDF 少 0.0001（例：年利率 10.00% → 推算 0.8333%，PDF 0.8334%）；沒有任何單一進位方式能讓 14 份全部吻合，因此採用容差。

PDF 內部另外要求：月配息率在 §9(1)、§14、§15(2)、§17(1) 都相同；年利率在 §9(1)、§14、§17(1) 都相同。

### 3.6 標的（2026-10-01 確認）

**目前只核對彭博（BB）英文代號**：

- PDF §10 彭博代號（去掉 ` Equity`）= 詢價表 BBG Code 1～5，依順序逐一相等，標的數量也要相同。
- 代號包含交易所尾碼，**逐字比對**。尾碼代表交易所，會影響報價，例如 `XXX UW` 與 `XXX UQ` 視為**不同標的**，不可互相對應或自動轉換。

中文名稱與交易所欄位不核對（2026-10-02 使用者確認：上手以代號索引自動帶入名稱，確認代號即可；見 §6.2）。標的介紹段落、價格表中的名稱也不核對。

#### 若日後恢復名稱核對（紀錄）

上手以彭博代號為準，再依代號對應的中文名稱填寫說明書。若日後恢復名稱核對，預定做法：

1. 以「上手＋彭博代號」為主鍵查標的對照表，取得中文名稱與交易所；
2. PDF 中文名稱與交易所 = 對照表；代號不在表內 → 轉人工覆核，不從 PDF 反推。

已知注意事項：
- 不同上手對同一標的的中文寫法不同（例：全名＋ADR／簡稱＋ADR／簡稱），對照表必須分上手；
- 同一家公司不同股票類別可能共用中文名稱，主鍵只能是代號；
- 「中文名稱」可能是英文公司名，照原字串比對；PDF 中英文名稱換行時要補回空白。

## 4. 判定原則

- 任何必核欄位抓不到、抓到多個不同值、或型態不屬於範本規格列出的寫法，都轉人工覆核，不猜值、不算通過。
- 「雙方皆無」（例：無 KI 商品的 KI 欄位）必須由 PDF 明確判斷為不適用，才算通過。
- 報告保留每一項的下單資料值、PDF 值與 PDF 出處（頁碼、座標）。

實作決定：

- **月配息率的期數**：第二階段起改用說明書配息表列數（第一階段暫用詢價表「天期 ÷ Observation Frequency」）；詢價表期數另由 `field.observation_frequency` 比對。
- **保證配息期（第二階段）**：表格為主來源。Daily Memory 的 §13(7) 定義句「就首個／第N個（即t等於N的情況）…指期末日N」→ N、「就t等於1至n…自相關期始日起（含）至相關期末日止（含）」→ 0，與表格不同時轉人工覆核；Daily 非記憶式與 Period End 沒有此句，只用表格。14 份樣本表格與定義句一致，8 份與舊整理表 Non-Call 推得值一致。
- **表格型態與日期規則（第二階段）**：Daily 非記憶式只有觀察期合併表（期末日即配息評價日、兼作提前出場表），只檢查 C4；Period End 非記憶式的評價日表兼作提前出場評價日，`schedule.autocall_dates` 為不適用。C4 的「平日」只排除週末。
- **商品名稱樣板的參數**：用說明書自身的天期（§13(1)）、幣別（封面）與是否記憶式（§15 觸發名詞）組出預期名稱，只檢查名稱格式；參數本身是否與詢價表一致由 `field.*` 規則負責，避免同一差異重複報告。§15 觸發名詞與名稱是否含「記憶式」不一致時轉人工覆核。
- **Monthly KI**：詢價表或說明書任一方判定為 Monthly KI 時，`field.ki_type` 轉人工覆核（尚無樣本）。
- **未涵蓋規則**：以固定清單列在報告「未涵蓋」區（`rules/barc.py` 的 `NOT_COVERED`），不影響整體狀態，也不代表通過。
