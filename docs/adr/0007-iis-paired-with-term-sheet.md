# 0007: 投資人須知與說明書成對核對，三方一致才回填

- Status: Accepted
- Date: 2026-10-08

## Context

每檔商品上手都交兩份 PDF：說明書（檔名結尾 `_TS`）與投資人須知（檔名結尾 `_IIS`，封面「中文投資人須知」）。過去只核對說明書，投資人須知由作業人員手工看（SOP：「IIS 共4頁」，產品條件、風險等級、警語等與說明書相同）。

把投資人須知加進批量核對時，有三個會長期影響結構的問題：

- **結果單位**：現在一份說明書就是一個核對單位，整份通過或人工放行即回填；同一批兩份 PDF 對到參考條件表同一列會全部轉人工覆核。說明書與投資人須知商品代號相同，照現狀會互相卡住。
- **比對基準**：投資人須知上的值要和誰比。參考條件表是核對條件的來源（[ADR 0004](0004-reference-sheet-as-check-source.md)），但 ISIN、商品中英文名稱、最低申購金額、標的中文名稱等不在參考條件表上，只有說明書有。
- **檢查點**：投資人須知只摘錄部分條件，且各上手寫法不同（BARC 有價格表與年利率，HSBC 只有幣別、面額、標的、年期、發行日、到期日；HSBC 沒有商品代號與 ISIN）。說明書有的審查標準項目（審查通過日期、受託機構負責人）投資人須知上沒有。

## Decision

- **一檔商品＝一份說明書＋一份投資人須知**。依檔名結尾 `_TS`／`_IIS`（嚴格比對，不容忍空白或其他寫法）分類，用檔名前 12 碼配對參考條件表與彼此。參考條件表一列最多對到一份說明書與一份投資人須知；同類有兩份以上仍屬「多份對到同一列」。
- **兩份都通過或人工放行才回填**。核對、狀態、人工放行與錯誤清單仍以一份 PDF 為單位；回填（進「回填後」）以商品為單位。缺同商品的另一份、檔名無法辨識都是配對問題：需人工覆核、不能人工放行。
- **三方一致用兩種比對達成**：投資人須知的值，參考條件表有對應欄位的和參考條件表比；沒有的和同商品說明書讀出的值比。說明書本來就和參考條件表比，所以三方一致；說明書錯時錯訊只出現在說明書，不在投資人須知重複。
- **檢查點依上手範本列舉**：只核對該上手投資人須知範本上實際有的項目（含審查標準類），各項的出處、次數、寫法差異寫在該上手的投資人須知規格；說明書有而投資人須知沒有的項目不核對，不推定通過也不報缺漏。投資人須知頁數必須剛好 4 頁（比外規「不超過 5 頁」嚴格）。

## Alternatives considered

- **投資人須知全部和說明書比**：參考條件表欄位會繞一手，說明書錯時兩份都報同一個錯；且偏離「參考條件表是核對來源」。
- **投資人須知全部和參考條件表比**：ISIN、名稱等參考條件表沒有的欄位就無從比對。
- **投資人須知獨立判定、不影響回填**：說明書通過就回填，投資人須知有錯的商品會被當成完成，與 SOP「TS/IIS 都核完才回寄」不符。
- **以商品為單位放行兩份**：錯訊分散在兩份文件，作業人員要一份一份看，放行仍以 PDF 為單位較直覺。
- **把說明書的審查標準規則整套套到投資人須知**：投資人須知缺的項目會全部轉人工覆核，次數與寫法（警語次數、名稱的「下稱」位置、HSBC 發行機構只寫中文）也不同。

## Consequences

- 批量預覽的配對改為以商品分組；「多份對到同一列」的判斷改成同類（說明書或投資人須知）各最多一份。
- 只有說明書、沒有同商品投資人須知的批次，不再能回填；要一起選兩份。原本可核對的檔名結尾不規則檔案（例：`_ TS`）改為檔名無法辨識。
- 每家上手要另外提供投資人須知範本的辨識、讀出與檢查點；BARC、HSBC 目前各只依 1 份樣本建立，遇到沒見過的寫法一律轉人工。尚未支援的上手（例：147）的投資人須知與說明書一樣是未支援上手。
- 審查標準設定多出投資人須知專屬的基準（固定警語次數等），與說明書的基準分開。
