# 0005: 上手 adapter 只提供標準欄位與說明書內部規則，參考條件表與審查標準規則各上手共用

- Status: Accepted
- Date: 2026-10-02

## Context

HSBC（Issue #34）上線後，BARC 與 HSBC 在同一套批量核對流程裡運作，但「各上手相同的部分」和「各上手不同的部分」沒有分清楚（Issue #49）：

- 同一張參考條件表有兩份比對規則，百分比、KI(%) 不適用、單位面額、rule_id 的語意已經不同。
- HSBC 有一份 Non-Call、ISIN、比價日規則永遠不會出現在報告裡，靠 rule_id 字串過濾。
- 審查標準的上手差異用共用規則上的開關處理（`issuer=`、`allow_international_phone=`）。
- 上手註冊項目有 12 欄 callable，單份核對順序寫死在批量入口，同一份說明書的範本辨識會跑三次。

對作業人員來說，同一欄位可能因上手不同而得出不同結論；對維護人員來說，改一條規則要改兩處，新增上手（例：SG，#27）就得再複製一份。

## Decision

- **上手 adapter 只提供四樣**（`src/fcn_checker/issuers.py` 的 `Issuer`）：
  - 識別資料：上手代號、範本 ID、名稱、parser 版本、未涵蓋清單。
  - 辨識 `detect`：文字行 → 是否為這家上手的範本（含證據）。
  - 讀出 `read`：文字行 → 說明書標準欄位（`standard_fields.STANDARD_FIELDS`）＋該上手規則需要的專屬資料；提前出場排程等擷取推導都在這裡完成。
  - 說明書內部規則 `rules`：只用讀出結果與審查標準，不碰參考條件表。唯一例外是 BARC 的月配息率推算（`derive.monthly_coupon`，表上年利率 × 天期 ÷ 12 ÷ 期數）：只有 BARC 條款寫出月配息率，使用者 2026-10-02 決定不作為共用規則（Issue #54）。
- **各上手共用的規則只實作一次**：參考條件表欄位規則（`rules/reference.py`）、審查標準規則（`rules/common.py`，依上手代號取得已解析的標準）、Non-Call／ISIN／發行日／比價日與回填（`rules/reference.py`、`backfill.py`）。
- **單份核對**（`single_check.py`）負責一份說明書的完整順序：配對結果 → 表頭欄位檢查 → 參考條件表欄位規則 → 上手說明書內部規則 → 審查標準規則 → Non-Call／ISIN／發行日／比價日 → 回填決策 → 整體狀態。一次核對中，每份說明書的辨識與讀出各只做一次。批量入口只負責載入、逐份呼叫、單份錯誤隔離與儲存。
- **語意差異以 BARC 為準**（使用者 2026-10-02 確認）：兩家同一規則語意不同時，一律採 BARC 現行規則與 rule_id。上手 adapter 沒交出某個必要標準欄位時，相關規則轉人工覆核並寫出欄位名稱。

## Alternatives considered

- **維持每家上手各寫一份參考條件表規則**：新增上手要複製第三份，同一欄位的結論會因上手而不同。
- **共用規則加上手開關參數**：每多一家上手，每條共用規則都要再加參數，差異散在各處。
- **上手註冊項目保留接線欄位（`isin`、`autocall_schedule`、`context` 等）**：介面寬、型別為 `Any`，新上手要接的東西多，且推導邏輯散在規則端。

## Consequences

- 新上手（例：SG）只要寫說明書擷取（交出標準欄位）與該上手專屬的說明書內部規則；參考條件表欄位、Non-Call、ISIN、發行日、比價日、回填與審查標準規則直接沿用。步驟見[新增上手實作規範](../issuer-onboarding.md) §6。
- HSBC 的結果依 BARC 語意調整（Issue #54、#55）；BARC 的核對結論不變。
- 規則的出處清單（例：HSBC 有兩個刊印日期）由各上手以標準欄位交出（`standard_fields.Occurrence`），共用規則逐處核對。
- 標準欄位清單成為 adapter 與共用規則之間的契約；新增共用規則需要的欄位時，要同步更新 `STANDARD_FIELDS` 與各上手的 `read`。
