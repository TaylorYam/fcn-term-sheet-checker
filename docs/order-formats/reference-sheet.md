# 參考條件表格式（所有上手共用）

- 設定檔：[`config/reference_sheet.toml`](../../config/reference_sheet.toml)（版面、欄位對照、允許值）、[`config/issuer_prefixes.toml`](../../config/issuer_prefixes.toml)（上手編號對照）
- 決策：[ADR 0004](../adr/0004-reference-sheet-as-check-source.md)。2026-10-02 起，所有上手的核對條件都來自參考條件表。BARC 詢價表已停用，PANEL 改版前暫時保留。
- 入口：`fcn-batch`（`fcn_checker.batch.run_batch`），見 README。
- 名詞：見 [CONTEXT.md](../../CONTEXT.md)

參考條件表是作業人員事先填好的 Excel（`FCN參考條件` 的 `樣本清單` 工作表），每列一檔商品，多家上手的商品放在同一張表。它同時是核對條件的來源，也是核對後要匯入資料庫的格式。

## 1. 版面

| 項目 | 內容 |
|---|---|
| 工作表 | `樣本清單`。同一個檔裡的其他工作表不讀取，回填時原樣保留 |
| 表頭 | 第 3 列 |
| 資料 | 第 4 列起，每列一檔商品；`TDCC Code` 空白的列略過 |
| 配對鍵 | `TDCC Code` = 說明書封面的商品代號（12 位，文字） |
| 上手 | `發行機構` 欄，寫法依上手：BARC = `Barclays`、HSBC = `HSBC` |
| 空值 | `-`（例：沒有 KI、沒有第 4 檔標的、不需要填的比價日） |
| 日期 | Excel 日期值 |
| 百分比 | 百分比數字（`75` 代表 75%） |
| 浮點尾數 | 例如 `x.xx0000000005`，讀取時先四捨五入到 9 位 |

表頭不在設定檔（`columns`、`ignored`）裡、缺少設定檔裡的欄位、或欄名重複時，每份說明書都會轉人工覆核。沒有表頭的欄位一律忽略（目前最右側有一個無表頭欄，存放已 KO 的註記）。

## 2. 上手編號與配對

1. 說明書 PDF 檔名的前三碼是**上手編號**，用 `issuer_prefixes.toml` 查出上手（`029` = BARC、`325` = HSBC）。
   - 上手編號不在對照表裡，或上手還沒有說明書範本 → **未支援上手**，不核對。
2. 說明書內容辨識出的上手必須與檔名一致，說明書商品代號的前三碼也必須等於檔名的上手編號；任一不一致就轉人工覆核。
3. 用說明書商品代號找 `TDCC Code` 相同的列：找不到或找到多列 → 人工覆核；該列 `發行機構` 不是此上手的寫法 → 人工覆核。
4. 同一批有兩份以上說明書對到同一列（例如同一檔商品的新舊版本）→ 這幾份全部轉人工覆核，都不核對、不回填，錯訊列出其他說明書的檔名（檔名相同時列完整路徑，同一個檔案選了兩次也會註明）；同一批的其他說明書照常核對和回填。預覽時也會顯示（Issue #70）。
5. 表上有列、但這次沒有選到 PDF 的，完全不會被動到。

## 3. 欄位

| 欄 | 標準欄位 | 處理 |
|---|---|---|
| TDCC Code | `product_code` | 配對與比對 |
| ISIN Code | `isin` | **回填欄位**（§5） |
| 單位面額 | `denomination` | 核對；另保留審查標準的「不等於幣別預設值 → 人工審查」 |
| 承作幣別 | `currency` | 核對 |
| 發行日 | `issue_date` | **回填欄位**（§5） |
| 交易日／最終比價日／到期日 | `trade_date`／`final_valuation_date`／`maturity_date` | 核對 |
| 比價日_1～12 | `autocall_date_1`～`autocall_date_12` | **回填欄位**（§4、§5） |
| KO(%)、K(%)、KI(%)、Coupon p.a. (%) | `ko_pct`、`strike_pct`、`ki_pct`、`coupon_pa_pct` | 依說明書顯示位數四捨五入後比對；沒有 KI 時 KI(%) 必須是 `-` |
| KO(Freq) | `ko_observation` | `D` 期間每日觀察、`P` 每期定日觀察 |
| KO(memo) | `ko_memory` | `Y` 記憶式、`N` 非記憶式 |
| KI(Freq) | `ki_type` | `-` 無 KI、`AM` 到期觀察、`D` 每日觀察 |
| 天期(月) | `tenor_months` | 核對 |
| Non-Call(月) | `first_callable_period` | 第一個可以提前出場的期別，最小為 1；填 0 會判定為不一致 |
| UL_1～UL_5 | `underlying_n` | 彭博代號（不含 ` Equity`），依順序比對，數量也要相同；沒有的標的填 `-` |
| UL_n_進場價／執行價／下限價／KO價 | `underlying_n_initial_price` 等 | 表上值四捨五入（half-up）到 4 位後與說明書價格表相等；沒有 KI 時下限價必須是 `-` |
| 庫存狀態、當日比價、Product、私銀註記、UF、UL_n_Memo | — | 存續或內部資訊，不核對 |

允許值不在表內 → 轉人工覆核。

## 4. 比價日填法

`比價日_n` 對應第 n 期，不需要填的期別填 `-`。

| KO(Freq) | 填法 | 日期 |
|---|---|---|
| `D` | 填 `比價日_{Non-Call}`（開始）與 `比價日_{期數}`（最後一期）；Non-Call = 天期時只填最後一格 | 開始那格：BARC 該期提前出場觀察期的期末日、HSBC KO 起日；最後一期：該期期末日（= 最終比價日） |
| `P` | 從 `比價日_{Non-Call}` 填到 `比價日_{期數}`（兩端都包含）；Non-Call = 天期時只填最後一格 | 各期自動提前出場評價日 |

填出來最晚的比價日必須等於最終比價日（MAX(`比價日_1`～`比價日_12`) = `最終比價日`），不符就轉人工覆核、不回填（Issue #69）。

以下情況轉人工覆核，不回填：
- 最晚的比價日不等於說明書的最終比價日。
- 期數超過 12。
- 期數與天期不同（格子無法對應）。
- BARC D 型第 1 期的期始日就有日期，也就是從第一天開始比價（S08、S10 型）。目前沒有已確認的參考條件表資料，還不能訂規則。

> 2026-10-02 曾改成 D 型只填 `比價日_{Non-Call}`；同日依作業人員實際匯入資料庫的表（`FCN參考條件_1001.xlsx`）恢復為「Non-Call 那期＋最後一期」（Issue #69）。

## 5. 回填

- 回填欄位只有 `ISIN Code`、`發行日`（BARC 第一章 §13(3)、HSBC 第一章 §15(2)；2026-10-02 起，Issue #64）與 `比價日_1`～`比價日_12`。
- 格子是空白：整份說明書核對 **PASS** 時才回填。
- 格子已經有值（包括 `-`）：跟說明書比對。相同就通過；不同就是不一致，保留原值。
- 說明書抓不到該欄的值（例如發行日）：轉人工覆核，不回填。
- 格式設定沒有回填欄位的欄名，或參考條件表少了該欄（例如沒有 `比價日_3`）：該份說明書的回填規則（`backfill.isin`／`backfill.issue_date`／`backfill.compare_dates`）轉人工覆核，訊息寫出缺的欄名，不回填（Issue #56）。
- 儲存前確認參考條件表與核對時相同（比對核對時記錄的 hash）；核對後被改過就不寫新檔，請重新核對。
- 結果另存成 `<原檔名>_回填_<YYYYMMDD-HHMMSS>.xlsx`，放在原檔同一個資料夾。原檔不動；檔名已經存在就不寫入（不覆蓋）。
- 新檔保留原檔所有工作表、公式與格式。回填的日期沿用表上既有日期格的顯示格式。
- 新檔多一張 `核對結果` 工作表，每份 PDF 一列：PDF 檔名、商品代號、上手、整體狀態（未支援上手另外標示）、問題數、問題摘要、已回填、報告檔名。原檔已經有同名工作表 → 整批錯誤，不產生新檔。
- 每份說明書另有 JSON／Markdown 報告（預設 `runtime/reports`），內容包括逐欄結果與每格回填決策。
