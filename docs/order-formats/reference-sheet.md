# 參考條件表格式（所有上手共用）

- 設定檔：[`config/reference_sheet.toml`](../../config/reference_sheet.toml)（版面、欄位對照、允許值）、[`config/issuer_prefixes.toml`](../../config/issuer_prefixes.toml)（上手編號對照）
- 決策：[ADR 0008](../adr/0008-reference-sheet-and-import-format.md)（取代 ADR 0004）。2026-10-02 起，所有上手的核對條件都來自參考條件表。BARC 詢價表已停用，PANEL 改版前暫時保留。
- 入口：`fcn-batch`（`fcn_checker.saving.run_batch`），見 README。
- 名詞：見 [CONTEXT.md](../../CONTEXT.md)

參考條件表是作業人員事先填好的 Excel，每列一檔商品，多家上手的商品放在同一張表。它可以是整理過的 `FCN參考條件`（`樣本清單` 工作表），也可以是公司原始的待建檔表：只要**必要欄**都在，多出其他欄、欄的順序不同都可以（Issue #199）。它同時是核對條件的來源，也是核對後要匯入資料庫的格式。

## 1. 版面

| 項目 | 內容 |
|---|---|
| 工作表 | 第一張工作表（活頁簿最左邊的分頁，不看名稱、不論是否隱藏）。其他工作表不讀取 |
| 表頭 | 前 10 列（`layout.header_search_rows`）裡有一格剛好是 `TDCC Code` 的那一列（`FCN參考條件` 是第 3 列，公司原始待建檔表是第 2 列）；表頭以上的列不讀。找不到或不只一列 → 整批錯誤 |
| 資料 | 表頭下一列起，每列一檔商品；`TDCC Code` 空白的列略過 |
| 配對鍵 | `TDCC Code` = 說明書封面的商品代號（12 位，文字） |
| 上手 | `發行機構` 欄（不是必要欄），寫法依上手：BARC = `Barclays`、HSBC = `HSBC`、MS = `MS`、BNP = `BNP`、SG = `SG`、Citi = `Citi`、JPM = `JPM`（Issue #233）、Nomura = `Nomura`（Issue #239）、GS = `GS`（Issue #248）、Natixis = `Natixis`（Issue #261）、CA = `CA`（Issue #274）、BBVA = `BBVA`（Issue #269）、UBS = `UBS`（Issue #279）、DBS = `DBS`（Issue #280） |
| 空值 | `-`（例：沒有 KI、沒有第 4 檔標的、不需要填的比價日） |
| 打勾 | `V`（半形英文字母，`TS`、`IIS` 欄；同表上「當日比價」「私銀註記」的寫法） |
| 日期 | Excel 日期值 |
| 百分比 | 百分比數字（`75` 代表 75%） |
| 浮點尾數 | 例如 `x.xx0000000005`，讀取時先四捨五入到 9 位 |

讀取依表頭的欄名找欄，只檢查**必要欄**（Issue #199）：

- **必要欄**：設定檔 `[columns]` 的欄名扣掉 `layout.optional_columns`（`TS`、`IIS`），也就是所有要核對的欄，加上表上有值時也要核對的回填欄位（`ISIN Code`、`發行日`、`比價日_1`～`比價日_12`）。同一標準欄位的欄名合起來算一欄：`承作幣別` 或 `計價幣別`（公司原始待建檔表的欄名）有一個就算有。
- 少了任何必要欄 → **整批錯誤**，一份都不核對，錯訊一次列出缺的欄（依匯入格式的欄位順序）。
- 會讀到的欄重複出現 → 整批錯誤，錯訊列出重複的欄：必要欄、`TS`、`IIS`、`發行機構`，以及 `承作幣別` 與 `計價幣別` 同時存在。
- `發行機構`：表上有這欄時確認該列是此上手的寫法（§2）；沒有這欄就不確認，商品代號前三碼已確定上手。
- `TS`、`IIS`：表上有就照 §5 回填與比對；沒有不影響核對。「回填後」是匯入格式，沒有這兩欄，改由 `TS/IIS完成檢核` 打勾（§5）。
- 其他欄（例如 `分公司_n`、`交易日期`、`下一比價日`、`TS/IIS完成檢核`、沒有表頭的欄）一律略過，重複也不提示。欄位順序不影響讀取。

參考條件表的欄位順序不影響核對結果檔：「回填後」一律照**匯入格式**（設定檔 `[import_format]`，§5）重新產生（Issue #203）。

> 2026-10-08 起（Issue #127）表上最前面有 `TS`、`IIS` 兩欄；2026-10-14 起（Issue #199）沒有這兩欄也照常核對。

## 2. 上手編號與配對

1. 說明書 PDF 檔名的前三碼是**上手編號**，用 `issuer_prefixes.toml` 查出上手（`029` = BARC、`325` = HSBC、`147` = MS、`082` = BNP、`037` = SG）。對照表另登記尚無範本的上手（CA、CITI、GS、JPM、NATIXIS、NOMURA、UBS、BBVA、DBS，Issue #149），這些商品是「未支援上手」，錯訊寫出上手代號；不在對照表的前三碼也是未支援上手。
   - 上手編號不在對照表裡，或上手還沒有說明書範本 → **未支援上手**，不核對。
2. 說明書內容辨識出的上手必須與檔名一致，說明書商品代號的前三碼也必須等於檔名的上手編號；任一不一致就轉人工覆核。
3. 用說明書商品代號找 `TDCC Code` 相同的列：找不到或找到多列 → 人工覆核；表上有 `發行機構` 欄且該列不是此上手的寫法 → 人工覆核。
4. 對到列後判斷**樣態**（Issue #207）：該列的 `期初定價`、`KO(Freq)`＋`KO(memo)`、`KI(Freq)`、`Non-Call(月)` 是否等於 `天期(月)`，以及說明書、同商品投資人須知明確讀出的同樣條件。任一邊是這家上手在**上手支援樣態表**（`issuer_prefixes.toml` 的 `[unsupported_variants]`）標為不支援的樣態 → 說明書與投資人須知都標「不支援樣態」，不跑其他規則、不回填、不能人工放行，錯訊寫出樣態與出處（例：「樣態：BARC 不支援「KI 每期觀察」（參考條件表）；…」）。表上只列不支援的樣態，沒列的組合（例：KO 每日觀察＋記憶式、KI 到期觀察、無 KI）一律算支援；讀不出或不在允許值內的值不判斷，照§3 的欄位規則處理。
5. 同一批有兩份以上說明書對到同一列（例如同一檔商品的新舊版本）→ 這幾份全部轉人工覆核，都不核對、不回填，錯訊列出其他說明書的檔名（檔名相同時列完整路徑，同一個檔案選了兩次也會註明）；同一批的其他說明書照常核對和回填。預覽時也會顯示（Issue #70）。
6. 表上有列、但這次沒有選到 PDF 的，完全不會被動到。

## 3. 欄位

| 欄 | 標準欄位 | 處理 |
|---|---|---|
| TS | `checked_term_sheet` | **回填欄位**（§5）：說明書核對沒問題打 `V`。不是必要欄 |
| IIS | `checked_iis` | **回填欄位**（§5）：投資人須知核對沒問題打 `V`。不是必要欄 |
| TDCC Code | `product_code` | 配對與比對 |
| ISIN Code | `isin` | **回填欄位**（§5） |
| 單位面額 | `denomination` | 核對；另保留審查標準的「不等於幣別預設值 → 人工審查」 |
| 承作幣別（或 計價幣別） | `currency` | 核對；兩個欄名同時出現算重複 |
| 發行日 | `issue_date` | **回填欄位**（§5） |
| 交易日／最終比價日／到期日 | `trade_date`／`final_valuation_date`／`maturity_date` | 核對 |
| 比價日_1～12 | `autocall_date_1`～`autocall_date_12` | **回填欄位**（§4、§5） |
| KO(%)、K(%)、KI(%)、Coupon p.a. (%) | `ko_pct`、`strike_pct`、`ki_pct`、`coupon_pa_pct` | 依說明書顯示位數四捨五入後比對；沒有 KI 時 KI(%) 必須是 `-`。說明書明確沒有的欄位不比對，結果為不適用並附說明（MS：說明書沒有年利率，改核對月配息率與年化報酬率）。Non-Call = 天期、說明書沒有 KO 價時（SG、MS）KO 視為期初價格的 100%，`KO(%)` 照常比對 100（見 [MS 下單資料格式](ms-fcn-reference.md) §3） |
| KO(Freq) | `ko_observation` | `D` 期間每日觀察、`P` 每期定日觀察 |
| KO(memo) | `ko_memory` | `Y` 記憶式、`N` 非記憶式 |
| KI(Freq) | `ki_type` | `-` 無 KI、`AM` 到期觀察、`D` 每日觀察、`P` 每期觀察（每個配息週期終止日，含期末定價日；2026-10-08 新增，目前只有 MS 範本會判成 `P`） |
| 天期(月) | `tenor_months` | 核對 |
| Non-Call(月) | `first_callable_period` | 第一個可以提前出場的期別，最小為 1；填 0 會判定為不一致 |
| UL_1～UL_5 | `underlying_n` | 彭博代號（不含 ` Equity`），依順序比對，數量也要相同；沒有的標的填 `-`。**Citi 例外**：依代號配對、不看順序，價格欄與回填也依代號（2026-10-14 確認，Issue #220；設定檔 `[underlyings] any_order_issuers`，見 [Citi 下單資料格式](citi-fcn-reference.md) §3）；**JPM 同 Citi**（2026-10-15 確認，Issue #233：JPM 說明書依英文公司名稱字母順序排列標的，見 [JPM 下單資料格式](jpm-fcn-reference.md) §3）；**GS 同 Citi**（2026-10-15 確認，Issue #248：GS 說明書依彭博代碼排序標的，見 [GS 下單資料格式](gs-fcn-reference.md) §3）。這三家代碼有一檔不同時照常判不一致，價格欄仍依代號配對：先比完整代碼，剩下的再比代號（不含交易所碼，例 `ABC UN` ↔ `ABC UQ`），兩邊都唯一才配；仍配不起來才依順序（2026-10-15 確認，Issue #265） |
| 期初定價 | `initial_pricing` | `開盤價`、`收盤價` 或 `VWAP`（作業人員放在 `KO(%)` 前一欄）；空白時當成不是 VWAP，價格照常比對，說明書寫明期初定價（Citi、GS）時改依說明書判斷（Issue #246）；其他值 → 轉人工覆核。決定價格欄怎麼處理（Issue #122）；說明書寫明期初定價時（Citi 標的表表頭「期初評價日之收盤價格／VWAP」；GS 第一章第 15 項「初始參考價格」的定義句，Issue #248）另須相同，其他範本沒有對應資料（標準欄位 `initial_pricing` 交 `absent`），不比對（Issue #220） |
| UL_n_進場價／執行價／下限價／KO價 | `underlying_n_initial_price` 等 | 表上值四捨五入（half-up）到 4 位後與說明書價格表相等；沒有 KI 時下限價必須是 `-`；說明書沒有 KO 價（SG、MS Non-Call = 天期）時 KO 價 = 期初價格，照常比對。期初定價為 `VWAP` 時不比對，改為**回填欄位**（§5） |
| 發行機構 | — | 不是必要欄；表上有才確認該列屬於此上手（§2） |
| 庫存狀態、當日比價、Product、私銀註記、UF、UL_n_Memo | — | 存續或內部資訊，不核對 |
| 其他欄（分公司_n、交易日期、下一比價日、TS/IIS完成檢核等） | — | 略過 |

允許值不在表內 → 轉人工覆核。

## 4. 比價日填法

`比價日_n` 對應第 n 期，不需要填的期別填 `-`。

| KO(Freq) | 填法 | 日期 |
|---|---|---|
| `D` | 填 `比價日_{Non-Call}`（開始）與 `比價日_{期數}`（最後一期）；Non-Call = 天期時只填最後一格 | 開始那格：BARC 該期提前出場觀察期的期末日、HSBC KO 起日、MS 該期配息週期終止日；最後一期：該期期末日（= 最終比價日） |
| `P` | 從 `比價日_{Non-Call}` 填到 `比價日_{期數}`（兩端都包含）；Non-Call = 天期時只填最後一格 | 各期自動提前出場評價日（MS：各期定價日） |

填出來最晚的比價日必須等於最終比價日（MAX(`比價日_1`～`比價日_12`) = `最終比價日`），不符就轉人工覆核、不回填（Issue #69）。

以下情況轉人工覆核，不回填：
- 最晚的比價日不等於說明書的最終比價日。
- 期數超過 12。
- 期數與天期不同（格子無法對應）。
- BARC D 型第 1 期的期始日就有日期，也就是從第一天開始比價（S08、S10 型）。目前沒有已確認的參考條件表資料，還不能訂規則。

> 2026-10-02 曾改成 D 型只填 `比價日_{Non-Call}`；同日依作業人員實際匯入資料庫的表（`FCN參考條件_1001.xlsx`）恢復為「Non-Call 那期＋最後一期」（Issue #69）。

## 5. 回填

- 回填欄位只有 `TS`、`IIS`（下一點）、`ISIN Code`、`發行日`（BARC 第一章 §13(3)、HSBC 第一章 §15(2)、MS 第一章 §14(3)；2026-10-02 起，Issue #64）與 `比價日_1`～`比價日_12`；VWAP 商品另加四個價格欄（再下一點）。
- `TS`、`IIS` 的值不取自說明書：說明書與投資人須知**都**通過或人工放行的商品，兩欄都填 `V`（人工放行的也填）。表上空白 → 回填；已是 `V` → 相同；`V` 以外的值（含 `v`、`-`、`✓`）→ 不一致、保留原值，跟其他回填欄位一樣不能人工放行（Issue #127）。表上沒有這兩欄（或其中一欄）時不影響核對（Issue #199）。「回填後」沒有 `TS`、`IIS` 欄，改由匯入格式的 `TS/IIS完成檢核` 一律填 `V`（留在「回填後」的都是兩份通過或人工放行的商品；Issue #203）。
- 期初定價為 `VWAP` 的商品，`UL_n_進場價／執行價／下限價／KO價` 也是回填欄位，但規則不同：整份通過或人工放行後，`UL_1`～`UL_5` 的價格欄**不論格子空白或已有值，一律覆寫**：說明書價格表上有的標的寫說明書的值（4 位小數），沒有 KI 時下限價寫 `-`；說明書沒有 KO 價（SG、MS Non-Call = 天期）時 KO 價寫說明書的期初價格（Issue #202）；說明書沒有的標的四欄都寫 `-`。表上原有的值不算「已有不同值」，不擋人工放行；原值記在核對紀錄（Issue #122）。
- 格子是空白：整份說明書核對 **PASS**，或作業人員在 PANEL 人工放行時才回填（格子已有不同值時不能人工放行）。
- 格子已經有值（包括 `-`）：跟說明書比對（VWAP 商品的價格欄除外，見上）。相同就通過；不同就是不一致，保留原值。
- 說明書抓不到該欄的值（例如發行日）：轉人工覆核，不回填。
- 格式設定沒有回填欄位的欄名：該份說明書的回填規則（`backfill.checked`／`backfill.isin`／`backfill.issue_date`／`backfill.compare_dates`／`backfill.underlying_prices`）轉人工覆核，訊息寫出缺的標準欄位，不回填（Issue #56）。參考條件表少了 `ISIN Code`、`發行日`、`比價日_n` 這些必要欄時是整批錯誤（§1）。
- 儲存前確認參考條件表與核對時相同（比對核對時記錄的 hash）；核對後被改過就什麼都不寫，請重新核對。
- 結果只有一份**核對結果檔** `<原檔名>_核對結果_<YYYYMMDD-HHMMSS>.xlsx`，存到 CLI `--out` 或 PANEL 儲存時選的資料夾（Issue #72）。原檔不動，也不再產生 `_回填_` 新檔；檔名已經存在就不寫入（不覆蓋）。整批錯誤（例如參考條件表讀不到）時不產生。
- 核對結果檔只有兩個工作表：
  - `回填後`：一律照**匯入格式**在新的活頁簿重新產生（Issue #203），比照公司原始待建檔表，不論參考條件表是公司原始待建檔表、作業人員模板或舊 `FCN參考條件`：
    - 第 1 列：A1 `最新交易日`、B1 留在「回填後」的列裡最晚的交易日（值，不是公式）。
    - 第 2 列：表頭，固定 80 欄（設定檔 `[import_format].columns`：`TS/IIS完成檢核`、`交易日期`、`Product`、`TDCC Code`、`ISIN Code`、`私銀註記`、`UF`、`計價幣別`、`單位面額`、`分公司_1`～`分公司_7` 與各自的 `_承作金額`、`交易日`、`發行日`、`比價日_1`～`比價日_12`、`下一比價日`、`最終比價日`、`到期日`、`期初定價`、KO／K／KI 各欄、`Coupon p.a. (%)`、`天期(月)`、`Non-Call(月)`、`UL_1`～`UL_5` 各 6 欄）。
    - 第 3 列起：整份通過（或人工放行）且已回填的列，順序照參考條件表。
    - 每格依欄名取參考條件表同名欄的值與顯示格式（回填欄位取回填後的值，回填的日期沿用表上既有日期格式）；同一標準欄位的其他欄名也算（`計價幣別` ← `承作幣別`）；`交易日期` 表上沒有時取 `交易日`（`fallbacks`）；`TS/IIS完成檢核` 一律 `V`；表上沒有的欄留空白。欄寬取同名欄。
    - 參考條件表上不在匯入格式的欄（`TS`、`IIS`、`庫存狀態`、`當日比價`、`發行機構`、沒有表頭的欄等）、其他工作表、公式、格式化條件、資料驗證、篩選、合併儲存格都不帶入。這個工作表可以直接匯入資料庫。
  - `錯誤清單`：表頭 `TDCC Code`、`PDF 檔名`、`錯訊`。每份沒通過且沒有人工放行的 PDF 一列，順序依 PDF 輸入順序；錯訊是中文錯訊（格式見 [CONTEXT.md](../../CONTEXT.md)「錯訊」），多條在同一格以換行分隔。找不到列、未支援上手、PDF 讀取錯誤也列入。`TDCC Code` 依序取 PDF 封面商品代號、檔名前 12 碼（12 位數字），都取不到時留白。
