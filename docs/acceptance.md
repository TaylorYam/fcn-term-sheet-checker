# 上線驗收流程

工具搬到公司電腦後，用最新交易逐一驗證每家上手的每種條件，確認工具判斷和人工核對一致、回補正確，才正式使用。本文件是步驟；進度記在驗收表 `data/上線驗收表.xlsx`（含真實商品代號，不進 Git）。

- 適用：已支援的上手（BARC、HSBC、MS），以及之後新增的上手（[新增上手實作規範](issuer-onboarding.md) §8「試跑」）。
- 一檔商品＝一份說明書（`_TS`）＋一份投資人須知（`_IIS`），兩份都通過才回填（[ADR 0007](adr/0007-iis-paired-with-term-sheet.md)）。

## 1. 驗收的單位與標準

- **單位**：上手 × 條件，例：「HSBC × KI 每日觀察」。不要求所有條件的排列組合；另外列出規格文件標為「未涵蓋」或會走不同表格的少數組合（§6）。
- **計入驗收**：一檔商品同時符合下列全部條件，才算這檔驗收了它符合的每個條件：
  - 交易日不早於**交易日下限**（目前 2026-06-11，受託機構最新審查通過日期）；
  - 說明書與投資人須知的工具判定都是「通過」（人工放行不算）；
  - 工具判定和人工核對結論一致；
  - 回補值（ISIN、發行日、比價日、`TS`／`IIS` 的 `V`；VWAP 商品另含各標的價格）都正確。
- **轉人工類條件**（工具還不支援，例：每月觀察 KI、MS 舊版範本）：工具轉人工覆核、人工也同意，就算驗收。
- **完成**：每個上手 × 條件至少 1 檔計入（目前設定，可在驗收表「設定」調整）。

## 2. 公司電腦準備（一次）

1. 安裝 Python 3.11 以上（官方版，含 Tcl/Tk）；公司禁止自行安裝時請 IT 協助。
2. 從 GitHub 取得最新版程式，放到自己有寫入權限的資料夾。
3. 雙擊 `setup_panel.cmd`，看到「安裝完成」；需要能連到公司允許的 Python 套件來源，PowerShell 被禁止時請 IT 協助（README「本機 PANEL」）。
4. 雙擊「Term Sheet 核對」捷徑開啟 PANEL，確認畫面上方的設定檔路徑是專案的 `config`。
5. PANEL「審查通過日期…」：確認最新一次仍是交易日下限那天；受託機構重新審查過就先新增，並同步改驗收表的交易日下限。
6. 把驗收表複製到公司電腦（依公司規定）。真實 PDF 與參考條件表只放公司電腦。

## 3. 每批：挑商品

1. 看驗收表「驗收總表」：還沒驗收的格子（0/1）就是要找的條件；先挑「開發樣本（參考）」裡交易日下限之後沒有樣本的條件。
2. 挑交易日不早於下限的最新交易；說明書與投資人須知都要有，檔名剛好是 `<12 位商品代號>_TS.pdf`、`<12 位商品代號>_IIS.pdf`。
3. 參考條件表要有這些商品的列：作業人員該預填的欄位照常填；`ISIN Code`、`發行日`、`比價日_1`～`比價日_12`、`TS`、`IIS` 留空讓工具回填。

## 4. 每檔：核對、回補、登記

1. **先人工核對**：照原本 SOP 核對說明書與投資人須知，記下結論（避免看了工具結果先入為主）。
2. **工具核對**：PANEL 選參考條件表 → 選 PDF（同一檔的 `_TS`、`_IIS` 一起選，可一次多檔）→ 預覽 → 開始核對。
3. **對照**：工具抓到的問題人工也同意嗎？人工發現的問題工具有抓到嗎？
4. **回補**（兩份都通過時）：儲存核對結果檔，開「回填後」確認回補值都和說明書一致，才用它做正式回補。
5. **登記**：驗收表「試跑紀錄」加一列：商品代號、交易日、條件（依參考條件表那一列選）、說明書與投資人須知的工具判定、工具和人工是否一致、回補是否正確。「計入驗收」欄顯示「計入」就完成；一檔商品會自動算進它符合的所有條件。

## 5. 有問題時

| 情況 | 處理 | 計入驗收 |
|---|---|---|
| 工具判錯：工具通過但實際有錯（漏報），或工具判錯但實際沒錯（誤報），或回補值錯 | 開 GitHub Issue，附 rule_id、錯訊、核對紀錄檔名（`runtime/核對紀錄/`）；依 [AGENTS.md](../AGENTS.md) Bug 流程修正。修好、更新程式後，同一檔再核對一次並新增一列 | 否（有誤判） |
| 商品本身有錯：工具判不一致，人工也同意（例：上手文件寫錯） | 照原流程退回上手；工具是對的 | 否，另找一檔 |
| 預期情況：舊版範本、受託機構商品代號空白、舊的審查通過日期、範本以外的寫法轉人工覆核（PANEL「待處理」） | 不是誤判 | 否，另找一檔 |

**Repo 是公開的**：Issue、PR 不寫真實商品代號、ISIN、價格、標的或客戶資料，用「驗收表試跑紀錄第 N 列」代替。

## 6. 驗收條件清單

驗收表「驗收總表」的列（編號與驗收表相同）。各上手不適用的條件顯示「—」。

| 編號 | 條件類別 | 條件值 | 參考條件表 |
|---|---|---|---|
| C01、C02 | KO 觀察方式 | 每日、定期 | `KO(Freq)` = D、P |
| C03、C04 | 記憶式 | 是、否 | `KO(memo)` = Y、N |
| C05～C07 | Non-Call | 第 1 期、中間期、只有最後一期 | `Non-Call(月)` = 1、介於 1 與天期之間、= 天期 |
| C08～C12 | KI 型態 | 無、到期、每日、每期（MS）、每月（BARC、HSBC；轉人工類） | `KI(Freq)` = -、AM、D、P、M |
| C13～C15 | 標的數 | 1 檔、2～4 檔、5 檔 | `UL_1`～`UL_5` |
| C16～C19 | 幣別 | 美元、日幣、人民幣、其他（轉人工類） | `承作幣別` |
| C20、C21 | 期初定價 | 開盤價或收盤價、VWAP | `期初定價` |
| C22、C23 | 範本版本（MS） | 新版、舊版（轉人工類） | — |
| G01～G05 | BARC 組合 | 每日／定期 × 記憶式與否（4 種 KO 表格）、定期＋有 KI | |
| G06～G08 | HSBC 組合 | 定期＋每日 KI、定期＋記憶式＋有 KI、每日＋非記憶式＋每日 KI | |
| G09～G11 | MS 組合 | 定期＋非記憶式＋中間期、每日＋中間期、多標的＋每日＋非記憶式 | |

目前暫不驗收（2026-10-09 決定先以美元、日幣為主）：人民幣與其他幣別（C18、C19），等有說明書樣本、確認中文幣別寫法後再處理（[TODO](TODO.md)）。

## 7. 上線判定

- **一家上手可以正式使用**：驗收總表該上手那一欄全部是「完成」或「—」，且沒有未解決的誤判。
- **一直等不到樣本的條件**（例：5 檔標的）：其他條件可以先正式使用；遇到這種商品時當驗收件處理（人工全核＋登記），驗收前不要直接用工具結果回補。
- **程式更新後**：`git pull` 後重新執行 `setup_panel.cmd`（只 `git pull` 不會生效）；修正影響到的條件，用一檔新商品再驗一次。
- **審查標準變動**（例：受託機構重新審查）：只改設定，並同步改驗收表的交易日下限。

## 8. 新增上手

新上手的規格與實作合併後（[新增上手實作規範](issuer-onboarding.md)），在驗收表：

1. 「設定」上手對照確認前三碼與上手代號（[上手編號對照](../config/issuer_prefixes.toml) 已登記 14 家）；
2. 「驗收總表」右邊空白的表頭填上手代號，那一欄就列出這家每個條件的驗收狀態；
3. 這家沒有的條件加進「設定」的不適用清單；這家特有的組合依驗收表「說明」新增一列；

再照 §3～§7 驗收。
